## 1. Product summary

An original 2D arcade run-and-gun shooter for the browser, in the style of late-1990s arcade
games: side-scrolling missions, one-hit deaths, weapon crates, grenades, an automatic knife at
close range, hostages that hand out items, vehicles the player can ride, route choices, large
multi-part bosses, and 2-player co-op.

- All art is pixel art **generated by code** at boot (no image files).
- All sound effects and music are **synthesized** with Web Audio (no audio files).
- Content and design: `docs/GAME_DESIGN.md`. IP rules: `docs/ORIGINALITY.md` (mandatory reading).

## 2. Hard rules (all agents, all code)

1. **TypeScript strict** with `erasableSyntaxOnly` (no `enum`, no `namespace`, no constructor
   parameter properties — declare fields explicitly) and `verbatimModuleSyntax` (use
   `import type` for type-only imports). Avoid `any`; if unavoidable, comment why.
2. **No runtime dependencies.** Dev dependencies only (vite, vitest, tsx, playwright, typescript,
   @types/node). No external asset files (no PNG/MP3/WAV/font files). Everything is code.
3. **Deterministic, headless-safe simulation.** Code in `src/engine/` and `src/game/` must not
   touch `window`, `document`, `navigator`, `localStorage`, `performance`, `AudioContext`,
   `requestAnimationFrame`, `Math.random`, `Date`, or `import.meta.env` — **except** in files
   named `*.browser.ts`, which may only be imported by `src/main.ts` or other `*.browser.ts`
   files. Gameplay randomness uses the seeded `world.rng`. Purely cosmetic randomness uses
   `world.fxRng` (also seeded) so headless runs stay reproducible.
4. **Fixed timestep 60 Hz.** All speeds are px/tick, all timers are ticks.
5. **Original content only.** Read `docs/ORIGINALITY.md` before writing any names, art, text or
   music.
6. **File ownership.** Each agent edits only the files and folders its task assigns. Other agents
   work in parallel in other folders. If you need a change in a file you do not own, make a local
   workaround inside your own files and list the needed change in your final summary.
7. **Fail soft.** Unknown sprite / sound / song / entity IDs must never crash the game: draw a
   magenta placeholder, play nothing, or spawn a placeholder entity, and `console.warn` once per ID.
   Content modules load with `Promise.allSettled`, so one broken module never stops the game.
8. **Quality gates before you finish:** `npm run typecheck` has zero errors in your files,
   `npm test` passes, and you looked at the visual output of your work (section 9).
9. **No CSS or asset imports** outside `src/main.ts`; no top-level `await` in `src/`.

## 3. Platform facts

- Logical resolution **384 × 216** (16:9). The display scales by the largest integer factor that
  fits (pixel-perfect), else best fit with nearest-neighbour. Letterbox is black.
- Coordinates in pixels, origin top-left, **y grows downward**.
- Simulation tick: 60 Hz fixed step. Rendering runs once per animation frame with the latest
  state (no interpolation). Hidden tab → simulation pauses.

## 5. Engine (`src/engine/`)

The signatures below are the contract sketch. Implementers may refine names and add features,
but must document the final API in this file. The files `color.ts`, `pixel.ts` (stub),
`render.ts` and `audio.ts` were pre-written by the orchestrator as shared interfaces so the
simulation side and the media side can be built in parallel: **extend them, do not break them.**

### 5.1 Math, RNG, events
- `math.ts`: `clamp`, `lerp`, `approach(v, target, step)`, `sign`, `wrap`, `dist`, angle helpers,
  `Rect {x,y,w,h}`, `overlaps(a,b)`, `contains(r,x,y)`, `rectAt(anchorX, anchorY, rel)`.
- `rng.ts`: `class Rng(seed)` — `next()` in [0,1), `int(min,max)` inclusive, `range(min,max)`,
  `chance(p)`, `pick(arr)`, `sign()`, `fork(salt)`. Deterministic per seed.
- `events.ts`: small typed event bus (`on`, `off`, `emit`) used by World and the game layer.

### 5.2 Input
- Buttons: `'left' | 'right' | 'up' | 'down' | 'fire' | 'jump' | 'bomb' | 'start'`.
- `VirtualPad` per player, updated once per tick from one or more sources: `held(b)`,
  `pressed(b)` (went down this tick), `released(b)`, `heldTicks(b)`. Edge detection lives in the
  pad, so all sources only report a raw "held" set.
- Sources: `KeyboardSource` + `GamepadSource` (`input.browser.ts`), `ScriptedSource` (headless,
  tests, bot, attract mode).
- Default keys — 1 player: arrows or WASD move, **Z/J fire, X/K jump, C/L bomb**, Enter start,
  Esc pause. 2 players: P1 = WASD + F/G/H (fire/jump/bomb) + 1 (start); P2 = arrows + ,/./
  (or numpad 1/2/3) + Enter. Bindings are rebindable and saved. Gamepad (standard mapping):
  X/Square fire, A/Cross jump, B/Circle bomb, Start start; d-pad and left stick move.

### 5.3 Colours & pixel art toolkit (pure TS, no DOM)
- `color.ts`: `type Color = number` packed **0xRRGGBBAA** (alpha 0 = transparent), `rgba()`,
  `hex()`, channel getters, `toCss()`.
- `pixel.ts`: `class PixelBuffer { w; h; data: Uint32Array }` storing packed 0xRRGGBBAA values,
  with: `get/set`, `fill`, `rect`, `strokeRect`, `hline/vline`, `line` (Bresenham), `thickLine`,
  `circle(cx,cy,r,c,fill)`, `ellipse`, `poly(points,c)` (scanline fill), `blit(src,dx,dy,
  {flipX,flipY,map,alpha})`, `outline(c, {corners})` (1px outline outside opaque pixels),
  `bevel(ramp, {light})` (auto-shading: lighter near light-facing edges, darker away),
  `dither`, `noise(rng, …)`, `replace(from,to)`, `trimBounds()`, `clone()`, `scaled(n)`.
- `ascii(rows, key)` → PixelBuffer from strings ('.' or ' ' = transparent) for small hand-made
  details (faces, icons, emblems).
- `palette.ts`: ONE curated project palette (40–64 colours) of named ramps dark→light
  (`PAL.ink`, `PAL.steel[0..n]`, `PAL.olive`, `PAL.sand`, `PAL.skinA/B/C`, `PAL.fire`, `PAL.sky`,
  `PAL.snow`, …). **All art uses palette ramps** — this keeps many agents' art cohesive.

### 5.4 Sprites & animation
- `Frame { buf: PixelBuffer; ox: number; oy: number; pts?: Record<string, [number, number]> }`
  — `(ox, oy)` is the anchor inside the buffer; drawing a frame at world `(x, y)` puts its
  anchor on `(x, y)`. `pts` are named attachment points **relative to the anchor** for the
  unflipped frame (flip negates x). Standard point names: `hip`, `muzzle`, `hand`, `head`, `seat`.
- `defineSprite(id, gen, opts?)` registers a lazily generated frame strip. IDs are slash paths
  (`char/<id>/legs-run`, `enemy/rifleman/run`, `fx/explosion-m`, `item/crate`, `ui/icon-bomb`).
- `getFrames(id)` (generates on first use, then caches), `frameCount(id)`, `hasSprite(id)`,
  `listSprites(prefix?)`, `preloadSprites(prefixes?, onProgress?)` (can yield between batches).
- `Animator`: `play(id, {ticksPerFrame, loop, restart})`, `update()`, `frame`, `index`, `done`.
- Missing ID → magenta placeholder frame + one `console.warn`.
- Renderers derive flipped and white "hit flash" variants lazily and cache them.

### 5.5 Rendering
`render.ts` defines `Renderer`. Implementations: `render-canvas.browser.ts` (Canvas 2D) and
`render-soft.ts` (pure TS into a PixelBuffer; used by node tools and tests). Both must give the
same image for the same calls. Key members (see the file for the full interface):
`begin(clear)`, `end()`, `setCamera(x,y)`, `sprite(id, frameIndex, x, y, opts)`,
`frame(f, x, y, opts)`, `image(buf, x, y, opts)`, `rect(x,y,w,h,color,opts)`,
`text(str, x, y, opts)`, `parallax(buf, factorX, factorY, offsetY, opts)`, `fade(color, alpha)`.
`DrawOpts`: `flipX`, `flash` (white silhouette), `alpha`, `screen` (ignore camera), `blend:'add'`.
Screen shake is a camera offset, not a renderer feature.

### 5.6 Fonts
`font.ts`: original bitmap fonts in code — `small` (≈5×7, caps, digits, punctuation) and `big`
(8×8 bold, titles). `measure(text, font)`. Colour, shadow/outline and alignment supported.

### 5.7 Audio
`audio.ts` defines `AudioOut` (`sfx`, `music`, `voice`, `setVolume`, `stopAll`; optional
`pauseMusic` / `resumeMusic`, `sfxLoop(key, id)` / `stopSfx(key)` for engines and drones,
`duckMusic(factor)`, `setMuted`, `suspend` / `resume`) and `NullAudio` (logs calls for tests).
`audio.browser.ts` implements Web Audio (context created/resumed on the first user gesture).
Music fails soft: an unknown or broken song logs one warning and the song that is playing goes
on; asking for the current song again keeps it going (a paused one resumes). The game never stops
on an audio error.
- `defineSfx(id, recipe)`: declarative synth recipes (oscillator layers, noise, pitch/filter
  envelopes, ADSR, distortion/bit-crush), pre-rendered once with `OfflineAudioContext`. Voice
  limits per sound and global.
- `defineSong(id, song)`: small tracker format — bpm, rows per beat, per-channel pattern strings
  (`'C4 . . E4 | G4 - - .'`), instruments (pulse 12.5/25/50 %, triangle, saw, noise kick/snare/
  hat, simple FM bell), order list and loop point; scheduled with a look-ahead timer.
  **Songs must be original compositions.**
- `voice(line)`: announcer via `speechSynthesis` if available and enabled, else a short jingle.

### 5.8 Camera
`camera.ts`: `x, y` (top-left), `follow(targets)`, forward **ratchet** (never scrolls back
against the section's scroll direction), clamp to section bounds, `lock(minX, maxX)` /
`unlock()` for arena fights, vertical follow with dead-zone for tall sections,
`shake(amount, ticks)`. Players stay inside the view (invisible walls at the view edges).

### 5.9 Terrain & physics
`terrain.ts` — static geometry of one section:
- `ground`: polylines (points sorted by x). Everything below a polyline is solid. Slopes up to
  about 1:1 are walkable; steeper parts act as walls.
- `platforms`: one-way polylines (land from above, jump through from below, drop through with
  **down + jump**).
- `solids`: axis-aligned rects that block from all sides.
- `hazards`: rects `{kind: 'pit' | 'water' | 'spikes' | 'lava' | 'kill'}`.
- Dynamic solids: entities can act as moving platforms / blocks (elevators, tank hulls,
  destructible walls) via the world.
- Queries: `surfaceY(x, yFrom, yTo, opts)`, `isSolid(x, y)`, `lineOfSight(x0,y0,x1,y1)`,
  `hazardAt(rect)`, and `cellAt(x, y): 0 | 1 | 2 | 3` (empty / ground / one-way platform band
  about 4 px thick under each platform line / solid rect) — the terrain painter samples this.

`physics.ts` — `Body` (anchor at feet centre: `x, y, vx, vy, w, h, onGround, dropThrough`) and
`moveBody(body, terrain, world?)`: slope following (step up / snap down), landing only when
falling onto a surface from above, ceilings, walls, one-way platforms, drop-through, and
sub-stepping so fast bodies never tunnel. Returns contact flags (`landed`, `hitWall`,
`hitCeiling`, `onGround`). Constants come from `src/game/tuning.ts`. **Unit tests required.**

### 5.10 Entities, World, collisions
```ts
type Team = 'player' | 'enemy' | 'neutral';
type DamageKind = 'bullet' | 'explosion' | 'fire' | 'knife' | 'laser' | 'crush' | 'impact';
interface Damage { amount: number; kind: DamageKind; dirX: number; source?: Entity; owner?: number }
```
`Entity` (abstract): `id`, `type`, `world`, `x, y, vx, vy`, `hitbox` (relative to anchor),
`team`, `tags`, `hp/maxHp`, `facing: 1 | -1`, `z`, `age`, `dead`, `invulnTicks`, `flashTicks`,
`update()`, `draw(r)`, `hurtboxes()` (world-space; bosses return several), `onHit(d)` (returns
true if the hit was absorbed), `die(d?)`, `onRemove()`, `despawnMargin`.

`World`: `entities`, `players`, `terrain`, `camera`, `particles`, `scripts`, `rng`, `fxRng`,
`tick`, `events`, `audio`. `spawn(id, x, y, params?)` via the entity registry (unknown id →
placeholder entity). Queries: `byTag`, `query(rect, filter)`, `nearestPlayer(x, y)`,
`alivePlayers()`, `onScreen(entity, margin)`. `damageArea(shape, damage, team)` for explosions.
Tick order: scripts → entities update (insertion order) → projectile vs hurtbox pass (by team) →
contact damage → particles → camera → cleanup (remove dead, despawn far off-screen).

### 5.11 Scripts (coroutines)
`script.ts`: generator coroutines for level events and boss patterns.
```ts
type Wait = number | (() => boolean) | void;           // ticks | predicate | next tick
type ScriptFn<C> = (ctx: C) => Generator<Wait, void, unknown>;
world.scripts.run(fn, { owner?: Entity })              // auto-cancel when the owner dies
```
Helpers: `wait(t)`, `until(pred)`, `waitCamera(x)`, `waitAllDead(list | tag)`, `all(...)`,
`race(...)`.

### 5.12 Particles & FX
`particles.ts`: pooled particles (pixel / rect / sprite-frame based): debris with gravity and
bounce, sparks, smoke, shell casings, dust, embers. Explosions are an animated fx entity +
particles + shake + sound, via a game-level helper; explosion damage goes through
`world.damageArea`.

### 5.13 Scenes, storage, loop, debug
- `scene.ts`: stack-based `SceneManager` (`push`, `pop`, `replace`, fade transitions); a scene
  has `enter`, `exit`, `update`, `draw`.
- `storage.ts`: `Store` interface + memory implementation; `storage.browser.ts` uses
  localStorage inside try/catch. Settings, bindings, high scores.
- `loop.ts`: pure fixed-step accumulator; `loop.browser.ts`: requestAnimationFrame driver.
- `debug.ts`: overlay toggles — F1 hitboxes, F2 fps/entity counts, F3 god mode, F4 skip to the
  next section/boss, F5 give all weapons. URL params (parsed in main.ts):
  `?mission=m1&section=b&god=1&debug=1&seed=42&players=2&char=<id>&weapon=<id>&boss=1&mute=1`.

## 6. Game layer (`src/game/`)

- `tuning.ts`: physics and gameplay constants (gravity, run speed, jump, coyote/buffer ticks,
  invulnerability…), informed by `docs/research/mechanics.md`.
- `session.ts`: `GameSession` — players (character, lives, score, bombs, weapon + ammo, rescued
  hostages), credits/continues, difficulty, mission/section/checkpoint, stats.
- `registry.ts`: `defineEntity(id, factory, meta)`, `defineWeapon(def)`, `defineCharacter(def)`,
  `defineMission(def)`; re-exports `defineSprite`, `defineSfx`, `defineSong`. Missing → placeholder.
- `player/`: Player entity — state machine; split upper/lower body; aim forward/up/down (down
  only in the air); crouch, crouch-walk, jump, fall, drop-through; shoot; throw bomb; automatic
  knife when an enemy is in melee range; mount/dismount vehicles; death and respawn with
  invulnerability blink; current weapon is lost on death (back to pistol).
- Base classes: `Projectile`, `Enemy`, `Boss` (multi-part hurtboxes, phases, damage states,
  death sequence), `Vehicle` (mountable, HP cells, own weapons, eject + ram attack), `Pickup`,
  `Hostage`.
- `hud.ts` (screen HUD + world-space speech bubbles and score pop-ups, all requested through
  `HudState` in `context.ts`), `settings.ts` (options content can read), `scenes/` (Boot, Title,
  Gameplay + Pause, Continue/GameOver, MissionComplete; Select, MissionIntro, Ending, Options and
  HighScores belong to the UI agent), `mission/` (mission runtime: sections, branches,
  checkpoints, the timer, auto-scroll, respawn rules, boss start/end, tally stats), `water.ts`
  (floating on water hazards).
- **Shared hooks for content** (details in `docs/api/game.md`): the enemy **reaction protocol**
  (`enemy.react(kind, ticks)` / `reactInArea` — anthem salutes, HONK ears, the JINGLE queue, SAY
  CHEESE …), shared enemy rules (attack tokens, `telegraphTicks`, gag awareness), the boss **part
  model** (`required` / `knifeable` / `contact` parts, `sequence`, `intermission`), vehicle rules
  (½ / 1 cell hits, eject window, ram = fire + jump, special = fire + bomb), status effects with
  physics / input / art / sound hooks (`defineStatus`), erasable enemy shots
  (`eraseEnemyShots`), damage `weapon` ids and `tags`, HUD bubbles / callouts / flashes, and
  per-section respawn rules, start vehicles, allowed vehicles and ice.
- `art/`: `humanoid.ts` (parametric human figure: style {skin, hair, headgear, top, pants,
  boots, build, accessories} + pose {limb angles, lean, crouch, aim, weapon pose}), `machines.ts`
  (wheels, treads, plates, rivets, barrels, rotors), `bg.ts` (skies, mountains, clouds, tree
  lines, skylines, parallax layer builders), `terrain-art.ts` (fills for ground polygons with
  top edges: dirt, sand, snow, rock, metal, wood…).

### 6.1 Human sprite contract (shared by art and logic agents)

Sizes: a standing adult is about **34–38 px** tall (feet to top of head/headgear), crouching
about 24–27 px. Player hurtbox 14×30 standing, 16×20 crouching (the physics body stays 14 px
wide). Enemy soldiers: 14×28 standing, 14×26 crouching (the crouched figure is ~27 px tall, so
standing shots hit it). All frames are anchored at the **feet centre** unless noted; lying death
frames rest on the ground line.

Playable characters — `char/<id>/…`:
- Lower body: `legs-idle`, `legs-run` (8f), `legs-jump` (2f), `legs-fall`, `legs-land`,
  `legs-crouch`, `legs-crouch-walk` (6f). **Every legs frame has a `hip` point** (where the torso
  attaches; it bobs during the run).
- Upper body, anchored at the **hip**, for weapon pose `<w>` ∈ `pistol | heavy`:
  `torso-<w>-idle` (≥2f), `torso-<w>-shoot` (≥2f), `torso-<w>-up`, `torso-<w>-shoot-up` (≥2f),
  `torso-<w>-down`, `torso-<w>-shoot-down` (≥2f), `torso-<w>-throw` (≥4f), `torso-<w>-knife`
  (≥4f); heavy only, optional: `torso-heavy-diag-up|diag-down` and `torso-heavy-shoot-diag-up|
  shoot-diag-down` (the machine-gun sweep at 22.5°–67.5°). Aim and shoot frames have a `muzzle`
  point; throw frames have a `hand` point. A status effect may swap any strip for
  `<art>/<infix>-<anim>` (e.g. `helium-legs-run`) when that variant is registered.
- Full body (feet anchor): `die` (≥6f), `die-burn` (≥4f), optional `die-blast` (explosions),
  `victory` (≥2f), `spawn` (≥3f), `bored` (≥4f, optional idle fidget), `mount` (≥2f); `portrait`
  (1f, about 32×32, for menus).
- **Rider strips for open-seat mounts (the Swan)**, upper body only, **hip anchor**, rig part
  `'upper'`, `weapon: 'none'`, points `head` and `hand` (no `muzzle`): `ride-sit` (2f, 20 ticks,
  loop), `ride-lean` (2f, 6, loop), `ride-up` (1f), `ride-hunch` (1f), `ride-hold` (2f, 4, loop),
  `ride-brace` (1f), `ride-duck` (1f), `ride-ears` (2f, 6, loop), `ride-cheer` (2f, 8, loop) —
  9 strips, 14 frames, for every playable character and `recruit`. Both hands hold the handle
  grips, except `ride-ears` (both hands open on the ears) and `ride-cheer` (near fist raised).
  No `mount-duck` frame (`ride-duck` replaces it). Pose tables and arm targets:
  `docs/design/swan-mount/look.md` §6.4. No `helium-ride-*` (a Helium Head player cannot mount).
- **Open-seat mounts:** the vehicle's `seat` point is the rider's **hip** (for cockpit vehicles it
  is the driver's feet). The rider is drawn with `Player.drawRide(r, x, y, flipX, pose, frame?)`
  (`RidePose` = the nine names above), with the invulnerability blink and the fallback chain
  `ride-<pose>` → `ride-sit` → `mount` frame 1 drawn 17 px lower (look.md §6.5–§6.6). The
  driver's anchor is not the seat: an open-seat mount overrides the protected
  `Vehicle.syncDriver()` and puts the mounted player's x, y on its own feet anchor (a flyer such
  as the Trumpeter: 15 px below its hull centre). Enemy AI reads a player's y as the feet
  (`Rifleman.upShot`, `Enemy.aimAt` and `canSee` at y − 15), so it then sees a grounded target.
  The `seat` point still places the rider and starts the eject.

Enemy soldiers — `enemy/<id>/…` (full body): `idle` (≥2f), `gag` (optional idle comedy, ≥4f),
`alert` (≥2f), `walk` (≥6f), `run` (≥8f), `crouch`, `shoot` (≥2f, `muzzle`), `crouch-shoot`
(≥2f, `muzzle`), `throw` (≥4f, `hand`), `panic` (≥4f), `die` (≥5f), `die-blast` (≥4f),
`die-burn` (≥4f), `die-knife` (≥4f). Optional (the game falls back when missing): `die-crush`,
`die-shatter`, and the reaction poses `salute`, `dance`, `confused`, `frozen`, `queue`, `ears`,
`photo-pose`, `stumble` (GDD §9.0).

Hostages — `item/hostage/…` (or `item/hostage/<kind>/…`): `tied` (≥2f), `freed` (≥3f), `walk`
(≥6f), `give` (≥4f, `hand`), `run` (≥6f), optional `bow`.

### 6.2 Mission data format (contract for mission agents)
```ts
interface MissionDef {
  id: string;                         // 'm0'..'m5'
  name: string; subtitle?: string;
  music: string; bossMusic?: string;
  start: string;                      // first section id
  sections: Record<string, SectionDef>;
}
interface SectionDef {
  id: string;
  width: number; height: number;      // px; height ≥ 216 (taller = vertical scrolling)
  scroll: 'right' | 'up' | 'down' | 'free';
  background: BackgroundDef;          // parallax layers from procedural generators
  terrain: TerrainDef;                // ground polylines, platforms, solids, hazards
  terrainStyle: TerrainStyleDef;      // how ground polygons and platforms are painted
  decor?: DecorDef[];                 // static props behind / in front
  playerStart: { x: number; y: number };
  checkpoints?: number[];             // camera-centre x ('right'), or y in 'up' / 'down' sections
  timeLimit?: number;                 // HUD counts of 256 ticks (≈ 4.3 s), default 60, 0 = none
  script: ScriptFn<SectionContext>;   // spawns, camera locks, set pieces, exits, boss
  exits?: ExitDef[];                  // { rect, to: sectionId, transition } — route choices
  respawn?: (p, ctx) => {x, y} | void;// section respawn rule (default: nearest safe floor in view)
  startVehicle?: string;              // players start (and respawn) mounted in this vehicle
  vehicles?: string[];                // vehicles that may be carried INTO this section
  iceRanges?: [number, number][];     // icy ground x ranges (players and vehicles slide)
}
```
The real types live in `src/game/mission/types.ts` (folder `src/game/mission/`); see
`docs/api/game.md` §10 for `SectionContext` (spawning, `enter` that never lands over a pit,
camera locks, `autoScroll(speed)`, `bossIntro(name, {subtitle})` which refills and pauses the
timer, callouts, exits) and `MissionDef` (`hostages` per section for the tally, `startBanner`,
`announce`, `clearLine`).
Builders keep terrain readable, e.g. `ground().at(0, 170).flat(400).slope(200, -40).gap(48)…`.

`BackgroundDef` and `TerrainStyleDef` are defined in **`src/game/art/art-registry.ts`** (a
pre-written contract):
- A background is `{ sky, layers: BgLayerDef[] }`; each layer names a generator registered with
  `defineBgGenerator(id, gen)` plus parallax factors. Standard generator ids (art agent):
  `sky-gradient`, `clouds`, `mountains`, `hills`, `treeline`, `jungle`, `city`, `ruins`, `dunes`,
  `ice-peaks`, `sea`. Mission agents may register their own generators.
- Terrain is painted in chunks by the painter set with `setTerrainPainter`, which samples
  `terrain.cellAt(x, y)`. A style names materials. Standard material ids (art agent): ground —
  `dirt`, `sand`, `rock`, `snow`, `ice`, `mud`, `metal`, `concrete`; edge — `grass`, `snow`,
  `sand`, `moss`, `rust`, `tiles`; platform — `wood`, `metal`, `rock`, `ice`; solid — `metal`,
  `concrete`, `crate`, `rock`, `brick`.
- Missing generators / painter fall back to flat placeholder art.

`DecorDef` (static props) is defined by the mission runtime: at minimum
`{ sprite: string; x: number; y: number; frame?: number; flipX?: boolean; front?: boolean }`.

## 7. Content manifest & registration

`src/game/content/index.ts` (owned by the orchestrator) maps manifest IDs to lazy imports.
At boot, `loadContent()` imports them with `Promise.allSettled`, logs failures, and the game
continues with placeholders. Every category folder has two entry files:

- `index.ts` — gameplay definitions (entities, weapons, characters…) for that category.
- `art.ts` — sprite definitions for that category (so art and logic can be built separately and
  `npm run sprites` can load art alone).

Mission and boss folders have a single `index.ts` that imports its own art. A category split
into sub-areas (`infantry/rhythm`, `vehicles/swan` …) gives every sub-area its own manifest
entries, so one broken sub-area never takes its siblings down; the category's top-level
`index.ts` / `art.ts` hold only shared helpers (except `infantry/index.ts`, which is `rifleman`).

## 8. Conventions

- z-order: decor-back 10 < items 20 < enemies 30 < vehicles 35 < players 40 < projectiles 50 <
  fx 60 < decor-front 80 < HUD.
- Teams: player shots and player explosions hurt only the `enemy` team (no friendly fire); enemy
  shots hurt the `player` team (players and player vehicles). Hostages are neutral and can't die.
- Conventional tags: `player`, `enemy`, `shootable`, `shot`, `soft` (knifeable), `boss`,
  `vehicle`, `hostage`, `cover` (riflemen hide behind it), `erasable` (enemy shots that tuba
  rings, HONK, the respawn POOF and boss intermissions remove), `legion` (Legion soldiers: they
  accept the anthem / JINGLE / HONK reactions). A prop built on `Enemy` is tagged `enemy` and
  holds `ctx.waitClear()` — remove the tag (or use another base) for props that must not.
- Damage: `Damage.kind` says what hit (`bullet explosion fire knife laser crush impact`),
  `Damage.weapon` which weapon, `Damage.tags` extra facts (`heavy`, `boss`, `shockwave`, `sonic`,
  `spread`, `hazard`; test with `damageHas`). The weapon → kind + tags table is in
  `docs/api/game.md` §6.
- Fairness (GDD §4.11): telegraphs ≥ 18 ticks (`telegraphTicks`), no attack from outside the
  view (check at the shot, not only at the wind-up), attack tokens, gags are free time.
- Balance numbers live in `GAME_DESIGN.md`, entity defs, and `tuning.ts`.
- Comments: short; explain non-obvious maths and timings.

## 9. Tooling (the agents' feedback loop)

- `npm run sprites -- [prefix]` → labelled contact-sheet PNGs in `tmp/sprites/` (3× scale,
  checkerboard behind transparent pixels). **Open the PNG with the Read tool and look at it.**
  Iterate until the art reads well at 1×.
- `npm run shot -- --mission m1 [--section a] [--x 1200] [--ticks 300] [--bot] [--every 60
  --count 6] [--seed n] [--out file]` → headless gameplay frames (software renderer) as a PNG.
- `npm run arena -- --spawn "id@+90;crate@+40{contains:bombs}" [--vehicle id] [--water 300-700]
  [--gap 900:48] [--platform x,y,len] [--hold right] [--press "30:jump"] [--trace id,player] [--every 15
  --count 6] --out tmp/arena/<you>.png` → entity sandbox: your entities in a real gameplay frame on a
  flat test section (floor y 170), per-tick traces and a JSON summary (`docs/api/slice.md` §8).
- `npm run sim -- --mission m1 [--god] [--max-ticks 72000]` → runs the bot autopilot headless
  and prints a JSON report (sections visited, kills, deaths, boss defeated, mission complete,
  errors with stacks, timing). The bot walks, jumps, climbs and drives ground vehicles; it cannot
  fly the m5-a shoot-em-up, swim or ride cable cars yet (see `docs/api/slice.md`).
- `npm run smoke -- [--port 5180]` → serves the game, opens headless Chromium (Playwright),
  plays scripted input, saves screenshots to `tmp/smoke/`, prints console errors. **Every agent
  uses its own port** (given in its task) because several agents run at once.
- `npm test` → vitest.

## 10. Performance budget

60 fps on a mid-range laptop with ≤ 300 active entities and ≤ 800 particles. No per-tick
allocations in hot paths (pool projectiles and particles). Sprites and backgrounds are converted
to canvases once and cached.

## 11. Definition of done (every task)

Typecheck clean for your files; tests pass; you looked at your sprites/screens as images; no
console errors in a smoke run of your feature; docs updated where you changed a contract; the
final summary lists files changed, IDs added, known issues, and requests for other owners.
